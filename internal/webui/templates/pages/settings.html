{{/* The settings groups. A group is one form with its own Save and Cancel. Saving it sends only its own fields, so another group's change is never saved with it. An unsaved change in another group survives only a save the script sends (see below); a page submission reloads the tab. The contract the script relies on: - [data-group] is the group, with its name as the value, and holds one [data-group-form]. The server answers a refused form with the whole tab, in which the same group shows the error and what was sent. - A control that holds a setting carries data-saved, the saved value ("on" or "off" for a switch). A password field has no saved value; it counts as changed once something is typed. [data-group-gate] marks what only confirms a save, such as the administrator password. - [data-group-refused] marks a group the server refused: its save bar stays shown, and Cancel follows its link to the tab as saved. [data-group-open] keeps the save bar shown while an action waits, although nothing was changed. - [data-show-if="name=value"] is shown only while that field of the same form has that value. Without the script everything is shown. - [data-group-native] asks the script to leave the form to the browser. The script sends a group's form itself, and keeps the page, only when the form has no password field (groupSave in owngit.js): while this browser's administrator confirmation is remembered or the check is off, a group shows no password field unless it always asks for one. A group that asks for the administrator password is an ordinary POST. Without the script every form is an ordinary POST, its save bar is always shown, and Cancel reloads the tab. With the script, leaving the page while a group holds a change asks first (leaveDialog below). */}}
